# Security policy and threat model

## Protected assets

NexaChat stores prompts, messages, uploaded documents, generated artifacts, contacts, model/search credentials, and outbound-message audit records. Production operators must treat the database and private artifact volume as confidential data stores.

## Implemented controls

### Identity and authorization

- Guest sessions receive a random owner id; registered users use scrypt password hashes.
- `AUTH_REQUIRED=true` disables guest access to data-bearing product routes.
- Every conversation, plan, upload, artifact, contact, preference, and WhatsApp query is scoped to the session owner.
- Unowned or unknown ids return 404 to reduce enumeration information.
- State-changing browser requests require a constant-time checked session CSRF token.
- Cookies are HttpOnly and SameSite=Lax; production supports Secure cookies and HSTS.

### Upload and artifact safety

- Server-generated filenames and private, non-public directories
- Configurable byte limits and post-extraction character limits
- Extension, MIME/signature, PDF header, image decode, Office ZIP structure, and UTF-8/JSON checks
- ZIP member count, uncompressed-size, and decompression-ratio defenses
- Formula-injection escaping in spreadsheet string cells
- Artifact download by owned database id rather than user path
- Structural reopen/validation before an artifact is marked ready
- Pluggable storage backend: local filesystem (default) or S3-compatible object storage

### S3 storage security

When `STORAGE_BACKEND=s3` is configured:

- The S3 bucket must block all public access; downloads use time-limited presigned URLs generated server-side after ownership verification.
- Object keys include a SHA-256 hash of the owner id; the application enforces ownership at the database level before issuing any presigned URL or loading object bytes.
- Presigned URL expiry defaults to one hour (`S3_PRESIGN_EXPIRY`) and should be kept short in production.
- S3 credentials (`S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`) must be stored in a secret manager, never committed to source control.
- IAM policies should grant only `s3:PutObject`, `s3:GetObject`, `s3:DeleteObject`, and `s3:HeadObject` scoped to the specific bucket ARN.
- Both web and worker services share the same bucket to ensure artifacts generated by background jobs are downloadable by the web process.

Antivirus scanning is an operator integration point, not simulated. Place an ICAP/ClamAV scanner in front of `/api/uploads` or add a quarantine job before public use with untrusted tenants.

### Network and research safety

- Only HTTP(S) is supported for fetches.
- Userinfo, loopback, private, link-local, multicast, reserved, and unspecified addresses are rejected after DNS resolution.
- Redirect targets are revalidated and response size/content type/time are bounded.
- Search/extracted text is labeled as untrusted data before model use.
- Current-data requests cannot use the demo provider; the server returns a refusal rather than fabricated rankings or citations.
- Provider errors are returned as safe messages while detailed traces stay server-side.

### Tool and action safety

- Every tool exposes JSON Schema and receives server-side validation.
- The calculator evaluates a restricted arithmetic AST; it does not call `eval`.
- Tool inputs/outputs, status, latency, and errors are persisted for audit.
- WhatsApp content is encrypted at rest and requires a separate prepare plus one-time confirm/send request.
- The WhatsApp provider adapter refuses any row without `confirmed_at` and `status=confirmed`.
- Meta webhook POST bodies require a valid `X-Hub-Signature-256` HMAC when `META_APP_SECRET` is configured.

### Runtime

- Secrets come from environment variables and are never returned in `/api/config`.
- CSP, frame denial, MIME-sniffing denial, referrer restrictions, and permissions policy are set.
- Flask-Limiter uses Redis when configured.
- Docker runs as a non-root user; Compose drops capabilities, enables no-new-privileges, and uses a read-only root filesystem.
- CI runs Ruff, mypy, pytest, Bandit, `pip-audit`, syntax checks, and a container build.

## Encryption details

`ENCRYPTION_KEY` should be a dedicated Fernet key. If omitted, a deterministic key is derived from `SECRET_KEY` for local convenience. Phone and email values use authenticated encryption. A keyed HMAC of normalized phone numbers enables duplicate detection without storing a plaintext search column.

Rotate keys through a planned decrypt/re-encrypt migration; changing the key without migration makes existing ciphertext unreadable. Do not reuse `SECRET_KEY` or `ENCRYPTION_KEY` across environments.

## Operator checklist

- Generate unique 32+ byte `SECRET_KEY`, Fernet `ENCRYPTION_KEY`, and webhook verification secret.
- Set `COOKIE_SECURE=true`, terminate TLS, and restrict trusted proxy headers.
- Set `AUTH_REQUIRED=true` before a public data-bearing deployment.
- Use managed PostgreSQL/Redis, encrypted disks, backups, and least-privilege network rules.
- Mount `/app/data` as a private persistent volume; do not serve it from a static web server.
- Limit provider billing, allowed models, upload size, rate limits, and retention.
- Place `/metrics` on a private network or protect it at the ingress.
- Configure malware scanning and a privacy/deletion policy appropriate to uploaded content.
- Use a long-lived Meta system-user token from a secret manager, verify webhooks, and review delivery logs.
- Verify logs and monitoring never record credentials, contact plaintext, raw files, or complete sensitive prompts.
- Run dependency audit and container scanning during every release.

## Residual risks

- Prompt injection cannot be fully eliminated; the design separates untrusted content and limits tools, but retrieved data can still influence generated prose.
- Local volume storage is not suitable for uncoordinated horizontal replicas.
- Browser sessions can be stolen through endpoint compromise or client malware; secure cookies and TLS reduce but do not remove that risk.
- A confirmed external message may be delivered irreversibly. The confirmation UI and audit trail reduce accidental delivery but cannot recall Meta messages.
- Rate limits are abuse controls, not a complete denial-of-service defense.

## Reporting

Report vulnerabilities privately to the repository owner. Include the affected commit, reproduction steps, impact, and suggested mitigation. Do not include live credentials, personal data, or destructive proof-of-concept payloads in a public issue.
